# 阶段 2：读路径 + 布隆过滤器 + 引擎类

日期：2026-09-28

## 布隆过滤器

- 最优参数推导：位数 m = -n·ln(p)/(ln2)²，哈希数 k = m/n·ln2（1% 误判率时
  每 key 约 9.6 bit、k=7）；
- double hashing 技巧：k 个哈希 = h1 + i·h2，只需算两个真哈希（h2 保证奇数）；
- **方向性是安全性的关键**：布隆只会把"不存在"误判为"存在"，绝不会反向——
  所以它只能用来"排除"，命中后仍要真的去查；
- 空间：每 key 约 1.2 字节（1% 误判率），换来不存在 key 的零 IO。

## 引擎读路径（版本规则是 LSM 的灵魂）

```
Get(k):
  1. MemTable          —— 最新
  2. L0 文件（新→旧）  —— 文件间可能 key 重叠，先命中者赢
  3. L1                —— 最老
  任何一层命中且是墓碑 → 立即返回"不存在"，停止向更老层查找
```

"墓碑截断"是最容易写错的规则：忘了它就会把已删除的 key 从老文件里
"复活"（僵尸数据）。

## 写路径

- Put/Delete 同时写 WAL（阶段 4 展开）和 MemTable；
- MemTable 达到阈值 → 冻结 → 顺序倒出成 L0 SST → 清空 WAL；
- 测试配置 memtable_limit=64KB，20000 次写产生了 10 个 L0 文件。

## 测试

20000 次随机 put/delete（3000 key 空间，大量覆盖/删除）→ 优雅关闭 →
重开全量对拍 + 5000 个不存在 key 全部正确（布隆无误判假阳性）。

## 观察与遗留

- l0_count=10 > trigger=4：compaction 还是空桩（阶段 3 实现）——
  L0 不压缩的读放大是线性的（10 个文件都要查），这正是 compaction 存在的意义。
