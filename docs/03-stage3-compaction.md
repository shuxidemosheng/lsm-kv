# 阶段 3：compaction（k 路归并）

日期：2026-09-28

## 策略选择

两级结构 + 全量归并（tiered 风格的简化版）：
- L0：flush 直出，文件间 key 可重叠，个数超阈值（4）触发归并；
- L1：所有 L0 + 旧 L1 归并出的**全量底级文件**（至多一个）。
- 没做 leveled（每层细粒度重叠控制）——工程复杂度陡增，教育版取舍。

## 归并规则（本阶段的灵魂）

1. 输入按 **新→旧** 排列（L0 按 id 降序，L1 最后）；
2. 多路线性找最小 key；**同 key 时最先出现的（最新版本）获胜**，
   其余版本跳过——"新版本说了算"的物理兑现；
3. **墓碑在底层归并时物理删除**：L1 之下没有更老的数据，
   "该 key 已删"的信息已经没有保护对象——这就是删除被推迟到此的原因。

## 崩溃一致性（简化但有底线）

- 新 L1 直接写最终文件名；若归并中途崩溃留下半个文件，
  Open 时 magic/footer 校验失败被跳过，**旧 L1 仍在兜底**；
- LoadDir 对 L1 从新到旧挑第一个能成功 Open 的（加固点）；
- 真实 LSM 用 MANIFEST 记录"当前生效文件集合"，比这个更严谨。

## 实测（20000 次随机写）

```
[compact] kept=2192 drop_tomb=575 -> l1-00000005.sst
[compact] kept=2421 drop_tomb=520 -> l1-00000010.sst
l0=2（低于阈值 4，收敛）
全量对拍通过（2994 keys）
```

写放大观察：两次归并分别处理了约 2767 和 2941 条输入，
这就是 LSM 用"写放大"换"读放大"的直接体现。
